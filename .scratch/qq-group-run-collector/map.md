# QQ 群对局数据小助手：实现地图

## 目标

群文件空间不够用，因此将游戏对局 ZIP 收集到本机，确认保存完整后清理对应群文件，持续腾出上传空间，并每天发一次贡献统计。收集和清理共同构成首版核心闭环，五项都需要实现。

## 第一版怎么做

- 使用 NapCat + OneBot 11 + NoneBot2/Python + SQLite + APScheduler，部署在用户另一台 24 小时开机的 Windows 电脑上。一个后台循环顺序处理扫描、下载和清理，暂不做多 worker 或通用任务框架。
- 只配置一个群、只收集群文件根目录。上传事件只触发扫描，登记以根目录列表为准；启动、重连和每 30 分钟也补扫。单次请求最多 1000 项，达到上限提示日志；不做递归或完整枚举大群文件库的承诺。
- 匹配 `run-YYYYMMDD-HHMMSS-NNNNNN.zip`，默认最大 256 MiB。流式下载、基本 ZIP 检查、本地保存、SQLite 记账即可。
- NapCat 文件 ID 会过期或随重启变化，因此用群号、busid、上传者、原名、大小和列表上传时间生成登记键，每次操作重新取得临时 ID。多个文件的这些字段完全相同时暂不处理，记日志供人工处理。每次可区分的上传独立保存，统计按 ZIP 的 SHA-256 去重。没有游戏内对局 ID 时，日报称“唯一包”。
- 次日 00:05 发前一天的上传次数、新增唯一包数和未收集成功数。失败看日志、修好后手动重试，日报需要时手动重发。
- 群文件自动清理是首版必做功能，正式运行配置启用；保留关闭开关供调试和暂停。每次收集成功及补扫后检查清理条件。本地文件必须存在且大小、SHA-256 与记录一致；再定位唯一远端候选，重新流式读取内容核对 SHA-256 后，用核对过的 ID 删除。通常每包下载两次，第二次不落盘。宽限期默认 24 小时，可配置为 0；本地归档不自动清理。

## 暂不做

- 双阶段归档协议、Windows 专用刷盘调用、断电耐久性承诺、校验版本历史、冲突隔离流程、进程会话审计和定期全库哈希巡检。
- 独立备份系统和备份凭据门禁。需要第二份副本时由使用者自行备份；本地一份文件仍可能因磁盘损坏丢失。
- 多群、多接入平台、嵌套目录补漏、Web 后台、复杂管理员命令、分布式队列和本地自动保留策略。
