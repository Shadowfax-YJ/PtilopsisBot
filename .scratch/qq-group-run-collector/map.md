# QQ 群对局数据小助手：实现地图

## 目标

群文件空间不够用，因此将游戏对局 ZIP 收集到本机，确认保存完整后清理对应群文件，持续腾出上传空间，并每天发一次贡献统计。收集和清理共同构成首版核心闭环，五项都需要实现。

## 第一版怎么做

- 使用 LLBot + OneBot 11 + NoneBot2/Python + SQLite + APScheduler，在同一台 Windows 主机运行一个进程。一个下载任务执行完再处理下一个，暂不做多 worker 或通用任务框架。
- 只配置一个群，主动扫描群文件根目录。收到上传事件就登记并下载，启动和每 30 分钟补扫一次；事件没有目录信息时直接收集，不额外查询文件夹位置。
- 匹配 `run-YYYYMMDD-HHMMSS-NNNNNN.zip`，默认最大 256 MiB。流式下载、基本 ZIP 检查、本地保存、SQLite 记账即可。
- 用源文件身份避免重复处理，每次上传独立保存，统计按 ZIP 的 SHA-256 去重。没有游戏内对局 ID 时，日报称“唯一包”，不承诺识别重新打包的同一局。
- 次日 00:05 发前一天的上传次数、新增唯一包数和未收集成功数。失败看日志、修好后手动重试，日报需要时手动重发。
- 群文件自动清理是首版必做功能，正式运行配置启用；保留关闭开关供调试和暂停。每次收集成功及补扫后检查清理条件，无需先观察一周。本地文件必须存在且大小、SHA-256 与记录一致；宽限期默认 24 小时，可配置为 0 以尽快腾空间。本地归档不自动清理。

## 暂不做

- 双阶段归档协议、Windows 专用刷盘调用、断电耐久性承诺、校验版本历史、冲突隔离流程、进程会话审计和定期全库哈希巡检。
- 独立备份系统和备份凭据门禁。需要第二份副本时由使用者自行备份；本地一份文件仍可能因磁盘损坏丢失。
- 多群、多接入平台、嵌套目录补漏、Web 后台、复杂管理员命令、分布式队列和本地自动保留策略。
