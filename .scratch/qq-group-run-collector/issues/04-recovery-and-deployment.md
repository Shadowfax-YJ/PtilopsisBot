# 补扫、重试和本机运行

Type: task
Status: implemented; live acceptance pending

## 实现

- 连接成功（包括重连）、上传事件和每 30 分钟触发根目录扫描，交由同一个后台循环串行执行。NapCat 默认请求 50 项，这里指定 1000 项；达到上限提示日志，不做通用能力探测、递归目录同步或全量防漏保证。手动 `scan` 返回 `queued` 后由后台执行。
- 每个文件处理失败后，隔 5 分钟改回待处理并从头重试，含首次下载在内最多自动尝试 3 次；耗尽后保持失败并记日志。检查不通过的不自动重试，需要时用本机入口重试。补扫不重置次数，也不反复排入已失败或成功的记录。
- 重启继续处理待处理记录，遗留 `.part` 由该记录下一次下载截断重写，不做断点续传。全盘巡检、无主文件隔离和数据库自动修复都不做。
- 数据目录剩余空间低于 2 GiB 时暂停下载和删源，留一条清楚的日志；空间恢复后继续。账号断开或数据库不可写时暂停相关操作，恢复后继续，不给每个文件反复累计这种环境错误。
- 管理通过本机配置和少量入口完成：立即补扫、重试指定记录、重发指定日期日报。正常停止/启动进程即可暂停/恢复；群里暂不提供管理命令或权限系统。
- 提供依赖声明、配置示例和一页运行说明，列出群号、OneBot access token、数据目录、文件上限、删源开关及宽限期。正式运行配置启用清理，确认机器人有群文件删除权限。OneBot 仅本机连接，密钥不提交；使用 SQLite、普通轮转日志，Windows 任务计划程序负责开机启动一份进程。
- 数据库也放在数据目录内。部署前关闭旧进程，需要备份时停机复制整个数据目录即可，不开发备份任务或健康仪表盘。

## 完成标准

在真实 NapCat 环境跑通约 100 MB 上传、本地保存后自动删除源群文件、重复事件、一次断网重连、NapCat 重启后的重新定位、补扫和日报发送。确认群文件已移除、本地 ZIP 仍可读；仅能下载而不能清理，不算首版验收通过。补扫能找回范围内根目录遗漏文件；失败可手动重试，磁盘不足能暂停。配置和运行说明足够在另一台常开 Windows 主机上重新部署机器人。
