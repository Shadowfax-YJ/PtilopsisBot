# 群文件清理与空间释放

Type: task
Status: implemented; live acceptance pending

## 实现

- 此项是首版必做功能，目的是释放群文件空间。正式运行配置使用 `auto_delete=true`，保留 `false` 供调试或临时暂停；不要求先观察一周，也不以独立备份系统作为上线前置条件。
- 每次收集成功和补扫结束时检查清理条件：上传记录已收集成功，且从成功时间起已满配置的宽限期。`delete_grace_hours` 默认 24，可设为 0，让检查通过的包立即释放群空间；待处理、失败、检查不通过的文件一律保留。
- 删除前检查该上传记录的本地文件存在，大小和重新计算的 SHA-256 与记录一致。不存在或不一致就跳过并记日志，手动重试收集；内容重复的上传也分别检查各自的文件和宽限期。
- 按登记键的全部上传字段重新枚举并定位唯一候选，取得新的 NapCat 临时 ID；再读取候选内容，SHA-256 与本地归档相同才用核对过的这个 ID 删除。不能只按文件名删除，也不在删源失败时悄悄换绑另一个 ID。低磁盘空间、账号离线或数据库不可写时跳过删源。
- 保存删除成功时间或最近错误即可。NapCat 返回的 QQ `result` 必须为整数 0 才算成功；仅 OneBot 外层成功不能代表 QQ 已删除。未找到、候选冲突、内容变化或返回值不明确时保留记录和错误，下次补扫再试，不做删除事件历史或回执协议。
- 删除后保留本地 ZIP 和上传记录，日报仍从 SQLite 统计；不能因群里已找不到文件就删掉贡献记录。
- 不自动清理本地归档。独立备份由使用者自行安排，不作为需要开发的前置系统；开启删源意味着接受本地磁盘损坏可能丢失这份数据。

## 完成标准

用专门测试上传跑通“下载 → 检查 → 本地保存并记账 → 删除群文件”，确认群文件列表中源文件已移除、本地 ZIP 可读、上传记录仍可用于日报。未完成这条流程，首版不算交付。

验证宽限期未满时保留、设为 0 时检查通过即可删除、关闭开关时不调用删除接口，以及权限失败后重试、重启后 ID 变化和源文件未找到的处理。失败记录、本地文件缺失或大小/哈希不符、远端内容变化或身份冲突时都保留群文件。
